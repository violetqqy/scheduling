# 班序 · 本地月度排班管理

纯前端项目，基于 Vue 3、TypeScript、Vite。所有排班数据保存在浏览器 IndexedDB；排班在 Web Worker 中计算；ExcelJS 在本地读取、生成 `.xlsx`。没有业务后端、服务器数据库、远程字体、CDN或外部数据上传。

## 启动

需要 Node.js 20.19+ 或 22.12+。

```sh
git clone git@github.com:violetqqy/scheduling.git
cd scheduling
npm ci
npm run dev
```

浏览器打开 [班序本地工作区](http://127.0.0.1:5178/)。也可以在 macOS 中双击 `启动班序.command`。开发服务只监听本机。

固定账号：`admin`；固定密码：`Admin@123456`。

## 首次使用

1. 首次打开使用空白工作区，不创建员工、班表或演示数据。工作台提供初始化步骤。
2. 只有名单时，选择“导入员工名单”，下载模板或映射自有Excel，核对后整批写入。
3. 有上月班表时，可直接导入并确认创建员工；也可先导名单再按编号导班表。没有上月时可跳过。
4. 确认年份月份、员工列、日期行和每种颜色的映射；有错误的数据不能直接写入。
5. 在“工作日历”调整开班日与员工预定休假计划，再生成目标月；没有上月记录也可以生成。
6. 在“月度排班”改单日或整个工作段；查看报告，解决硬冲突后确认版本。
7. 从“统计分析”选择维度、日期及版本，查看明细或导出当前表。

## 已实现功能

- 固定账号登录、会话退出、八项管理菜单、响应式侧边栏。
- 工作台月份切换（上月、下月、直接选择、回到本月），统计与预览同步联动。
- 工作台、员工×整月表、自然月视图、逐日八班配对、房间颜色与班次文字。
- 当月班次一键清空，保留休息、预定休假和事后请假，原版本可找回。
- 任意月份（含尚未自动排班）、任意员工和日期可直接编辑；多选、整行、整列、Shift连选允许全部状态互改，普通人工班默认锁定，冲突可保存但不可确认。
- 工作日历仅含开班日历和员工预定休假；月度表编辑不反写计划，修改日历和实际状态无需填写原因。支持自定义名称班次及独立加班，自动生成保留且不占八班名额。
- 员工新增、修改、停用、名单顺序调整，同名员工用编号区分。
- 四房间八班次，启用需求固定2人，允许关闭整个班次；整月需求日历支持单日、不连续多日、日期范围和整月开班日批量设置，休息日跳过，未指定班次保持原配置。
- 周末默认休息，全局开班调休、月度员工休假计划矩阵；实际休息、休假、请假与恢复可用在月度表中编辑。
- 有上月时一键续排；无上月时从本月首日开始，跳过上月相关要求，补空位或重排未锁定格，保护预定休假/事后请假/休息/人工锁定。
- 先分析上月并推导续段、早晚顺延、休假递延和光子转白任务，再生成目标月。历史早晚欠项优先补达；当月按名单优先完整早段和晚段，提前考虑剩余工作段及必经中段；生成报告单列早晚达成人数，容量不足明确提醒。
- 有原中/光子/白班段依据的休假未完成，自动生成唯一来源月任务，下月在早晚目标之后补排；JSON保留来源。
- 允许人工段内混班，逐日每班仍需2人；P05提醒不阻止确认；有原段依据的单日调整按原类别达成，多日混班不计完整段。自动段内仍同房间同班。
- 完整早晚目标之后，月内优先安排至少两个普通班房间；按工作段分散，不改变段内班次。无法达成提示P04，保留人工安排；员工统计新增房间数及分布。
- 红黄普通班按工作段早→中→晚→早循环，白班/光子/自定义不推进顺序；跨月原段先续完，历史保留快照，违序人工安排提示H07。
- 按开班日历识别4/5/6天工作段，休假/请假不切段；早中晚分别按上月同类别房间天数取相反房间，平票取最后一次；跨月先续原班，光子可续完但该员工本月不新开光子段。
- 缺口与超额报告、个人优先目标提醒、不可将有硬冲突的草稿确认为有效版本。
- 草稿/确认/导入版本，历史保留、修订副本、输入变化提醒、操作记录。
- 员工、工作段、日期班次、房间、班次类别、轮转、递延、异常及自定义名称九类统计；筛选、合计、下钻与导出。
- Excel矩阵及结构化明细导入，颜色映射、未知标记/日期/重复数据检查、新员工确认、整批事务写入。
- 有色Excel导出（班表、人员统计、配对、明细、休假计划、事后请假、员工资料、图例），可重新导入。
- JSON完整备份与恢复，本地写入失败保持旧数据，多窗口写入冲突阻止覆盖。

## Excel格式

### 员工×日期矩阵

推荐表头第一行：员工编号、姓名、1、2、3……，数据从第二行开始。姓名在第2列，编号在第1列，日期从第3列开始；自己的原表可以在导入界面调整。

颜色映射：红房间/橙房间早中晚、蓝房间白班、无色房间光子；深灰/黑为休息，黄为预定休假，紫为事后请假。可手动确认近似色和主题色。早中晚必须能确定红或橙房间，不静默推断。

尾部U忽略，`定位`只作为附注。`加班`导入为独立状态，保留原休息或预定休假，计入出勤并单列；不占八班配对名额，不计算工时。

### 结构化明细

每行一名员工一天：`日期 | 员工编号 | 姓名 | 房间 | 班次 | 锁定`。导出文件的“排班明细”工作表可直接用于此形式；也可以映射其他列序。完整日期支持Excel日期或`YYYY-MM-DD`。

只支持 `.xlsx`；旧 `.xls` 需要先另存。文件最大10MB，单表最多处理1000条员工数据行。请勿把月标题、合计行放入数据区域；数据区合并单元格需拆开。

导入不会逐格复刻用户提供的截图。本项目未取得真实Excel，当前验证使用人工构造文件。

## 排班实现与边界

先保留保护格与跨月已知班次，再以工作段为约束，逐日做最小费用最大匹配，在多个确定性候选中依次比较覆盖、历史早晚欠项、按名单的当月完整早晚目标、其他递延、月内房间分散和历史房间偏好。整段白班、光子或预定休假允许早晚欠项自动顺延，实际达成和允许顺延分开显示。完整段内已分配班次保持一致，人员可有未分配日，搭档可变。

这是有约束的候选生成器，不是完整的全局整数规划求解器。复杂随机休假可能存在可行解但本次候选未找到，界面会明确报告，不能将此情况宣称为“已证明无解”。确认版本前另有全月硬约束校验。

PRD待决定项的处理：

- 光子跨月固定续完原段，该员工本月不新开光子段，不提供切换。
- 预定休假、请假、手工休息、自定义和加班不切工作段；边界由开班日历确定。
- 完整段按开始月归属，人天按实际发生月份统计；跨月未执行完不提前记完整。
- 不强制每人每月中、光子、白各一段；自动追踪有原班段依据的休假递延及光子转白任务，也可手工登记其他有来源任务。
- 多于每日16人需求时，余人标记未分配，不自动新增备用班或休假。
- 同月红橙混排按上月实际早中晚中红房间天数较多形成转橙偏好；橙转红未被视为硬规则。
- 只保证当前导入/查看的历史版本可追溯。修改上月、日历、名单或规则后，后续草稿需要重新核对。

## 本地数据与登录

本版采用全新的第2版本地工作区（`banxu-local-v2`），不迁移或兼容旧数据。JSON恢复只接受第2版结构。

数据按浏览器和网站地址隔离，不同浏览器、端口或域名不会自动共享。清理网站存储会清除本地数据；建议定期导出JSON完整备份。Excel不包含全部历史版本和操作记录，不能替代JSON备份。

固定口令写在 `src/store.ts` 的 `LOGIN` 中。登录使用 `sessionStorage` 管理当前标签会话。纯前端登录可被设备使用者检查和绕过，不是服务器鉴权，也不加密浏览器数据；这与仅前端、本地存储的架构一致。

## V1.1 休假计划调整

工作日历只保留开班日历与员工休假计划，支持非连续日期、编辑和取消。临时请假、休息等状态在月度表编辑，不反写独立计划。月度表所有状态均可互改，不填原因；人工普通班默认锁定，解锁后按计划重排。自定义和加班保留且不计八班覆盖。Excel和JSON保留实际状态及自定义名称；计划与实际分别核对。

## V1.2 首次排班与初始化导入

- 工作台提供目标月份、员工导入、可选历史导入、日历与休假配置、生成入口。
