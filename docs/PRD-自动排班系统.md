## A 产品概述

版本：V1.11。日期：2026-11-04。

本系统面向排班负责人。以员工名单、目标月日历及休假为输入，生成月度排班草稿。有上月记录时延续轮转；没有上月记录时按其余规则首次排班。负责人在月历中检查缺口、改班并确认版本，统计表与该版本同步。

本文包含产品需求、数据字典、排班流程、线框图与验收要求。配套纯前端系统已实现。本版先分析上月并自动推导跨月续段、早晚顺延、休假递延与光子转白任务，再生成本月排班。整段白班、光子或预定休假允许未完成早晚段顺延；单日人工调整按原班段达成。红黄班按早中晚循环，并保留上月相反房间偏好。

月度表支持任意月份、员工、日期和状态编辑，新增自定义班次。工作日历与实际班表分开维护。

需求依据是用户提供的五月、六月截图及后续文字说明。黄色格已明确为排班前预定休假，请假用于排班后调整。截图没有明确年份，仅用于理解结构与图例，不将截图中的每个历史安排当作新规则的标准答案。

已按 [phuryn/pm-skills](https://github.com/phuryn/pm-skills) 的 create-prd、user-stories、test-scenarios 方法完成拆分。开源技能提供分析框架，业务规则来自用户说明。

本文约定三类标记：**已确认**是用户明确提出；**方案建议**是本稿提出的产品处理方式；**待决定**是尚不能唯一确定的业务口径。待决定项不得作为已批准算法实现。

## B 背景与问题

现有表格以员工为行、日期为列，颜色表达房间，文字表达班次或特殊状态。人工排下月班时，需要同时核对上月轮转、跨月工作段、随机请假、每日两人配对与名单顺序。

直接复制上一月再修改容易覆盖休息或请假，也难以解释为何某人没有排到早班或晚班。人数不足时，系统必须说明缺口，不能通过单人班、重复安排同一员工来拼出完整表格。

用户新增了统计要求。因此同一份排班数据应同时支持月度查看、员工统计、房间统计、班次统计及跨月轮转核对。

已确认的房间与班次：

| 房间编号（建议） | 房间展示 | 允许班次 | 每个启用班次人数 |
| --- | --- | --- | --- |
| ROOM-B | 蓝底房间 | 白班 | 2人 |
| ROOM-R | 红底房间 | 早班、中班、晚班 | 每班2人 |
| ROOM-O | 橙底房间 | 早班、中班、晚班 | 每班2人 |
| ROOM-P | 无色底房间 | 光子班 | 2人 |

合计四个房间、八个班次。在八班都启用的日期，需要16名不同员工。系统中的房间名称可由负责人改成实际名称，颜色只是房间的展示属性。

## C 目标与成功标准

支持两条流程：已有历史时导入并生成下月；没有历史时先导入员工，再配置日历与休假直接排班。两者均支持手工修订、确认与统计。

以下是产品验收目标建议，不是已经测得的成效：

| 指标 | 验收目标 | 衡量方式 |
| --- | --- | --- |
| 受保护单元格 | 自动生成覆盖休息、预定休假、事后请假及人工锁定格的次数为0 | 比较生成前后值与锁定状态 |
| 排班有效性 | 可确认版本中，启用班次全部恰好2人，员工同日最多1班 | 对整月逐日校验 |
| 跨月可追溯 | 每个续排工作段和递延任务都有来源 | 从月历进入段详情和递延清单 |
| 未满足可解释 | 所有缺口、跨月硬冲突与软目标未满足都有原因 | 检查生成报告与统计 |
| 统计一致性 | 所有统计可回到明细核对，且绑定同一排班版本 | 对照员工、日期、房间明细汇总 |
| 响应时间 | 建议以50人、31天为首版基准，10秒内给出结果或明确求解中状态 | 由开发阶段建立基准并实测，不承诺任何输入均有解 |

保存有冲突的编辑草稿与确认有效排班是两种状态。草稿可保留用户修改，但不得把缺人或单人班标为有效排班。

## D 使用人群与使用场景

| 用户 | 主要任务 | 首版入口 |
| --- | --- | --- |
| 排班负责人（主要用户） | 维护员工和名单顺序、休假、导入、生成和改单元格 | 月度排班、基础资料、导入 |
| 排班核对者（建议角色） | 检查班次人数、跨月轮转和统计，确认排班版本 | 冲突报告、统计、版本详情 |

两种任务可由同一个人完成。首版不要求建设复杂的审批组织；谁能编辑、谁能确认可先设为简单权限。

关键场景：新增员工后排下月班；月末同班继续到月初；请假导致原搭档变动；调休后周六开班、工作日休息；生成后改某人某日的班；主管查看月度人员与房间负荷。

## E 用户价值

| 价值要素 | 排班负责人 | 排班核对者 |
| --- | --- | --- |
| 谁 | 每月制作排班表的人 | 检查排班与统计的人 |
| 为什么 | 需要同时满足多人、多班、多月规则 | 需要发现缺口并核对轮转情况 |
| 目前做法 | 对照上月Excel逐格填写 | 逐行逐列点人数，另做统计 |
| 系统如何帮助 | 自动保护休假、按规则生成、提示冲突 | 按版本汇总、按原因筛选、点击查看明细 |
| 预期变化 | 保留人工控制，减少重复填写和漏查 | 发现问题后能定位到人员、日期与规则 |
| 可用替代 | 继续使用Excel和人工核对 | 手工汇总Excel透视表 |

系统的核心价值是把轮转、跨月、保护格与两人配对放在同一次校验中，并能解释没有排满的原因。实际节省时间需在试用中测量。

## F 方案与功能需求

### F1. 信息结构与主流程

```flow LR
首次准备 -> 员工导入: 只有名单
首次准备 -> 历史导入: 有班表，可同时建员工
员工导入 -> 历史导入: 可选
员工导入 -> 月度准备: 无上月也可继续
历史导入 -> 月度准备: 使用历史轮转
月度准备 -> 自动生成: 工作日历与休假计划
自动生成 -> 月历修订: 草稿与报告
月历修订 -> 人工状态调整: 不反写工作日历
人工状态调整 -> 月历修订: 查看冲突
月历修订 -> 校验确认: 检查规则
校验确认 -> 统计与导出: 绑定版本
```

工作台提供上月、下月、直接选择月份和回到本月入口，复用全局所选月份。切换后在册员工、开班日、成组率、冲突、排班预览及房间人天同步更新。无班表月份显示空态；查看完整排班、日历、导入、生成等快捷入口沿用所选月份，生成面板明确目标月。

主导航包括月度排班、员工管理、房间与班次、工作日历、Excel导入、统计分析、规则与版本。首版只做一个排班单元，多部门隔离留待后续。

### F2. 员工管理

- 新增、编辑、停用员工；使用唯一员工编号，同名人员不得自动合并。
- 维护姓名、排班顺序、生效日期、离职/停用日期、备注。
- 可调整名单顺序。生成前展示顺序，生成结果保存顺序快照。
- 历史已被排班引用的员工以停用处理，保留历史排班与统计。
- 新员工没有上月记录时展示“无历史”，不编造上月房间或光子经历。
- 不存固定搭档。两人组合随实际可用情况形成。

员工是否限制房间或有固定岗位尚未确认。首版不默认存在特殊岗位豁免；后续可扩展可排班次范围。

**员工名单Excel导入**

支持只含员工资料的工作表，无需日期或班次。字段为员工编号、姓名、顺序、生效日期、停用日期、备注；可映射自有表头。

姓名必填。无编号时按唯一姓名匹配现有员工，无法匹配则自动编号。同名歧义和重复编号必须处理，不能自动合并。

顺序从1开始，留空时保留已有顺序，新员工按文件顺序追加。日期可留空；新员工表示不限，已有员工保留原值。停用日期起不再排班，必须晚于生效日期。

预览新增/更新人数、具体资料及逐行错误，可跳过错误行。相同编号更新需明确勾选确认；不删除未列入的员工，不生成班表。整批保存，失败不写入部分数据。

### F3. 房间、班次与需求管理

- 预置四房间、八班次，保存独立编码、名称、显示颜色及启用状态。
- 班次绑定房间，分别识别红早与橙早，同时保留“早班”这一统计类别。
- 需求按日期、房间和班次保存。启用时人数固定2，关闭时为0。
- 默认开班日八班全开，允许按日关闭班次；保存写入操作记录。
- 本期无需配置具体上下班时间。没有真实班次时长前不计算工时。
- 黄底预定休假、紫底事后请假和深灰/黑底休息是人员状态，不是房间，也不加入八班次。

**月度需求日历**

- 用整月周一至周日日历替代逐日切换；支持上月、下月和直接选择月份。
- 每天显示开班/休息、启用班次数、所需人数、各房间启用班次数及单日配置标记。
- 单日模式点击日期后在侧栏设置八班启闭，统一保存；休息日只读并提供工作日历入口。
- 多选模式支持不连续日期、日期范围、全选开班日和清除选择。范围选择替换当前选择，休息日自动跳过且不可选。
- 每个班次提供保持不变、启用2人、关闭0人、恢复默认。跨日期不一致时显示部分启用，默认保持不变，避免覆盖无关班次。
- 提供全部启用、全部关闭、恢复默认快捷操作；预览变更数量后整批保存，失败不写入部分数据。
- 恢复默认删除日期覆盖，跟随全局班次开关。全局停用班次不能单日启用，须先修改全局开关。
- 切换月份清空日期选择及未保存动作，切换单日或模式清空未保存动作；页面明确提供保存按钮。
- 配置仅用于后续生成，已有版本的需求快照和班表保持原样；输入变化提醒继续生效。

**验收：**单日修改只影响该日指定班次；批量选择不连续日期仅修改这些日期。选择含周末的范围只处理开班日，调休开班日可选。保持不变保留各日差异，恢复默认消除覆盖；刷新页面仍保留已保存配置。旧班表不变，新生成版本采用更新需求。

### F4. 工作日历与员工预定休假

工作日历固定两个页签：开班日历、员工休假计划。取消事后请假和个人休息配置入口。请假、休息等实际状态统一在月度排班修改。

- 开班日历默认周末休息，可逐日改为开班或休息；无需输入修改原因。开班日决定八班需求，个人休假不减少全体需求。
- 员工休假计划按员工×自然月表格展示，可新增、编辑、取消单日或不连续日期。可按范围选择开班日或全部日期。
- 计划仅限任职有效期内、当前月的有效日期；同一员工同日不能重复建计划。休假说明选填。
- 计划是独立记录，版本保留计划快照。月度表改班、休息、请假、自定义不会反写或删除计划。
- 计划修改更新计划来源的默认格；人工实际安排、自定义、加班及锁定班次保留。计划与实际不一致时在月度表提示。
- 取消计划只恢复计划来源格，原有人工覆盖不被删除。已确认版本通过修订草稿处理。
- 计划日期统计与实际状态统计分开，同一实际日期只计一种状态。

验收：只显示两个页签；不填写原因可保存开班状态。月度表把黄色预定休假改成普通班后，计划表仍显示原预定休假。再次生成时按人工锁定策略处理。

### F5. 历史数据与Excel导入

首版建议支持 `.xlsx`，兼容两个输入模板：员工×日期的历史表，以及结构化明细表。旧 `.xls` 提示转存为 `.xlsx`；CSV可后续支持，但不能保留底色。

导入按四步进行：选择文件与用途 → 映射表头、人员、日期、颜色、文字 → 预览并解决错误 → 确认写入。

导入用途分为员工名单、上月历史、排班前休假计划、排班后事后请假、个人休息、目标月人工排班。计划和请假分别选择用途，空白格不撤销已有记录。

| 项目 | 处理要求 |
| --- | --- |
| 人员识别 | 优先员工编号；仅姓名匹配时需消除同名歧义；新员工由用户确认创建 |
| 日期 | 表头只有日数时必须选择年份和月份，校验月份实际天数 |
| 房间识别 | 底色映射到房间；支持深灰映射休息，黄底映射预定休假，紫底映射事后请假 |
| 班次识别 | 早、中、晚、白、光子映射到班次类别，尾部U忽略，但保留原文 |
| 加班 | 独立状态，保留原休息或休假，计出勤并单列，不占八班需求 |
| 非排班文字 | 定位保留原始附注，不参与需求和轮转 |
| 未知标记 | 不默认当休假或空白；阻止受影响数据确认，要求修正映射 |
| 颜色文字冲突 | 如蓝底写早班，展示冲突并要求确认；不静默当成白班 |
| 合并单元格 | 表头按预览映射；人员日期区域的跨格歧义需人工解决 |
| 历史有效性 | 可导入有历史例外的数据并标警告，不能将历史警告自动变为新规则豁免 |
| 写入与回退 | 确认前不影响现有版本；同批次全成或全败；重复导入先展示差异 |

主题色、近似色及条件格式产生的显示色都需要可确认的映射。读取不到实际底色时要求人工映射，不猜测。图片没有Excel原始单元格数据，本稿未宣称已导入或验证真实工作簿。

**F5.1 首次初始化方案**

首次打开默认使用空白工作区：没有员工、班表或演示安排。保留四房间八班次和默认周末日历。演示数据仅由用户在设置中主动载入。

| 用户已有资料 | 初始化路径 | 后续操作 |
| --- | --- | --- |
| 只有员工名单 | 导入员工名单，核对编号、顺序和有效日期 | 配置当月日历与休假，直接首次排班 |
| 已有上月班表 | 可直接导入班表，确认创建未知员工 | 使用该历史生成目标月；无需重复录入名单 |
| 名单与班表都有 | 先导名单，再按编号匹配已有班表 | 保留员工主键，不重复创建 |
| 均无Excel | 在员工管理手工添加 | 配置休假后首次排班 |

工作台显示三个步骤：准备员工、导入上月（可跳过）、配置日历与休假后生成。支持选择目标月。导入上月时默认该目标月的前一月，历史导入完成回到初始化步骤。

没有在职员工时禁止生成并提供导入入口。八班全开需要每日16人；人数不足仍报告缺口，不因首次使用放宽两人成组。

提供两份空白模板：“员工名单模板”只含员工资料及说明；“初始化导入模板”含员工名单、已有排班及填写说明。模板不附带虚构员工行。已有排班可填写“红早/橙晚/白/光子”等明确文字，或使用映射底色。

### F6. 数据库与数据字典

数据库建议按以下业务实体拆分。编号、颜色和实体名称是实现建议；字段用于约束功能，开发时可按技术方案调整。

| 实体 | 核心字段 | 关系与约束 |
| --- | --- | --- |
| Employee 员工 | id、code、name、sort_order、active_from、active_to | 编号唯一；姓名不唯一；历史引用不可随停用删除 |
| Room 房间 | id、code、name、color、active | 房间颜色不作主键 |
| Shift 班次 | id、code、room_id、category、active | category为早/中/晚/白/光子；一班归一房间 |
| CalendarDay 全局日历 | date、is_open | 日期唯一；周末默认关闭，允许覆盖 |
| Demand 每日需求 | date、shift_id、required_count | 日期+班次唯一；本期只允许0或2 |
| VacationPlan 预定休假计划 | id、employee_id、month、dates[]、reason、source、created、updated | 独立于实际班次；同员工同日唯一；支持不连续日期 |
| ActualStatus 实际状态 | version_id、employee_id、date、kind、source | 月度表的休息、休假、请假等实际状态；不反写计划 |
| ScheduleVersion 排班版本 | id、month、status、parent_id、history_mode、source_version_id、rule_version、input_snapshot | 草稿/有冲突草稿/已确认/历史导入；生成依赖可追溯 |
| Assignment 排班明细 | version_id、employee_id、date、shift_id、customName、locked、source、segment_id | 同版本员工+日期唯一；休息/休假/请假/加班/自定义是明确状态；加班保存overtimeBase原状态 |
| PairAssignment 两人班组 | version_id、date、shift_id、member1、member2 | 两成员不同；一人同日不能属于两个组；成员对应两条Assignment |
| SegmentBaseline 原段依据 | employee_id、start、dates、shift_id、excluded_dates | 单日人工调整按原类别达成，不按多数推断；清空副本移除依据 |
| WorkSegment 工作段 | id、employee_id、start、end、boundary_status | 跨月使用同一段标识；边界未知时不可标完整 |
| RotationLedger 轮转递延 | employee_id、type、origin_segment、due_month、status、fulfilled_segment | 区分续段、待白班、其他递延；同来源任务不重复建立 |
| GenerationRun 生成批次 | id、base_version、target_version、order_snapshot、status、duration | 保存输入快照、规则版本、排班前续段数量和待补任务清单与结果报告 |
| ConflictIssue 冲突 | run_id、rule_id、severity、employee/date/shift、reason、suggestion | 能从报告定位回月历；不以颜色代替错误类型 |
| ImportBatch 导入批次 | id、file_name、purpose、mapping、raw_data、errors | 保存原文与颜色信息，支持差异预览与批次追溯 |
| ChangeLog 修改记录 | actor、time、entity、detail、source_version | 人工改班、日历变更、确认版本均可追溯 |

纯前端实现使用本地数据结构第2版，保存在独立工作区。不迁移或兼容旧版数据、旧版JSON备份。Excel黄色格按本版休假定义解析。

排班版本保存当时的休假计划快照。查看或导出历史版本时，不使用后来修改的计划覆盖历史。

PairAssignment可在实现中由排班明细派生，但提交前必须校验每个启用班恰好形成一对。统计应从版本对应的排班明细汇总，不另存一份可被随意修改的统计总数。

### F7. 工作段、跨月与递延

工作段由开班日历的连续开班日确定，不固定五天，可因调休成为4天或6天。任职生效和停用构成员工有效边界。

预定休假和月度请假只扣除不可用日，不切段。月度手工休息、自定义和加班也不改变段边界。周一至周五开班、周三休假时，前后可用日仍属同段。

月末不切段，跨月必须续原房间原班。相反房间偏好仅作用于新工作段，不能将未结束的红早在月初改成橙早。

完整普通班段须至少一天有效普通班，全部可工作日期执行同房间同班；整段休假不算完成。自定义、手工休息或普通工作日加班不能用于获得完整早晚目标。完整段归属起始月，人天归实际日期。

无上月版本时，从当月起点开始，跳过历史轮换、历史光子触发和跨月继承；其余规则继续执行。有上月但续段班次缺失时报告，不虚构历史。

上月完整光子段产生白班目标和当月新光子禁排。光子跨月固定允许续完原段，该员工本月不得再新开光子段。其他员工可继续补光子需求。白班无法完成时可递延；中、白、光子不强制每人每月各一段。

递延按员工、来源和目标类别记录。完成以确认版本的完整段核对。

V1.10增加有原班段依据的休假递延：

- 休假或请假替换原中班、光子或白班时，记录原班次、原工作段日期和被替换日期。
- 若当月该类别未完成，自动登记下月任务。同员工、来源月和类别仅生成一项，说明中保留原班段范围。
- 部分休假后，其余可用日期仍完成原类别，不产生欠班。同月已在另一段完成该类别，也不重复欠班。
- 无原班次依据的预定休假不虚构中、光子、白班任务。完整白班、光子或整段预定休假可作为早晚顺延依据，自动生成下月补达任务；没有该依据的早晚缺项仍报告P01。
- 取消假期或恢复原类别完整段后，同步撤销对应自动休假任务。人工登记任务和光子转白任务保持独立。
- 下月在硬约束内先补历史早晚欠项，再保障当月早晚目标，最后补中、白、光子任务。光子禁排与早中晚顺序仍优先，排不下的任务继续保留。
- 已确认完整段才标为完成；重排已确认月份时，重新保障该月任务，不能误用被替换旧版的达成结果。
- 原班段来源随JSON备份保留，Excel班表不是完整备份。旧数据没有该来源时不追溯猜测。

### F7.1 早晚顺延与生成前分析（V1.11）

- 当月有一个已完成白班段、光子段，或一个整段预定休假时，允许早段、晚段中尚未完成的类别顺延至下月。
- “允许顺延”与“已达成”分开显示。仍尽量在当月达成，不能为制造豁免而安排零散白班或光子。
- 工作段按开班日历边界、任职日期和原跨月来源确定；休假、请假不切段。已完成段按起始月归属，跨月尚缺后续记录不提前算完成。
- 整段事后请假、部分预定休假、自定义和零散班次不单独产生早晚豁免。整段计划根据版本中的预定休假快照核对，月度人工修改不反向改计划。
- 早晚任务按员工、来源月、类别去重；缺早晚两个类别时分别生成。保留来源段范围和原因，恢复来源目标或取消唯一依据时自动撤销。
- 下月一个已确认完整早段或晚段，可同时满足该月对应目标与历史同类别补达任务，不额外要求再排一段。草稿仅显示实际达成，确认版本后才核销。
- 生成时直接从有效版本推导任务，无需用户提前打开统计或手工登记。上月参考可为确认、导入或草稿，报告标明来源；无上月时跳过缺失历史条件，仍处理已存在的更早递延。
- 生成报告保留本次排班前的来源版本、续段数量和待补任务清单。更改上月后重新生成会重新分析；重复生成不重复追加相同任务。
- 原班段依据随JSON完整备份保存。Excel班表导入表示实际安排，不凭混班表格猜测原段类别。

简易流程线框：

```text
[选择目标月] → [读取上月有效版本、历史未完成任务]
                       ↓
[分析：跨月原段｜早晚缺项｜休假原段｜光子转白｜房间偏好]
                       ↓
[固定本月日历、休假计划、人工保留格] → [按约束生成本月草稿]
                       ↓
[报告：历史任务清单｜实际早晚达成｜允许顺延｜硬冲突]
                       ↓
[手工调整、核对每日2人] → [确认版本，核销已完成任务]
```

### F8. 自动排班规则

**完整早晚段优先（V1.10）**

- 每人优先完成一个早班工作段和一个晚班工作段。长度按两次日历休息边界确定，不按固定五天或累计五个人天代替。
- 4天、6天和其他长度均按实际工作段核对。部分休假扣除不可用日，不切段；整段无可用日期不算完成。
- 在覆盖和硬约束内，按员工名单逐人比较早晚缺项。先保障靠前员工，再由其余人员补剩余需求。
- 提前考虑剩余可结束工作段，以及早→中→晚循环的必经中段。不能只给早晚班单日加分后逐日贪心分配。
- 先比较覆盖与硬约束，再按名单比较历史早晚欠项和当月完整早晚目标。其后比较其他递延、房间分散和历史房间偏好。
- 月底跨月段先续完整段，未结束前不提前记为完成。统计仍按工作段起始月份归属。
- 房间分散和中/光子/白班任务不能挤占完整早晚目标。
- 人数与完整段容量不足时，不突破每天每班2人。报告P01，列出已完成早晚段数和跨月待续段数。
- 例：四个完整工作段、每天红橙早班各2人，最多有16个完整早段名额。18人无法都取得早段，按名单优先满足。
- 月度表和生成报告分别显示完整早段、晚段及同时达成人数。无硬冲突不等于个人目标全部达成。

**月内房间分散（V1.9，优先级由V1.10修正）**

- 在覆盖、硬约束及完整早晚目标之后，每人当月优先安排至少两个普通班房间。
- 按房间ID去重，红、橙、白班和光子各算一个房间。红早换红中仍是同一个房间。
- 自定义、加班、休息、预定休假、请假和未分配不算房间。跨月段只计当月实际安排。
- 以完整工作段换房间，不在同一段内部强行切换。红黄房间变化不重置早中晚顺序。
- 生成时同时参考本月已排和未来保留格。后段已锁在红房间时，前面可调段优先尝试其他房间。
- 候选按覆盖、历史早晚欠项、当月完整早晚目标、其他递延、月内分散、历史房间偏好依次比较。该目标不要求房间天数均分，也不要求每人遍历四房间。
- 若只能排到一个房间，报告P04提醒。检查可排段数、假期、需求开关和保留班次，不伪造第二个房间。
- 人工锁定、跨月续班、光子禁排、段内一致和早中晚顺序优先。仅补空位仍保留已有普通班，重排才重新分配未锁定班。
- P04为优先目标提醒，不单独阻止确认。无普通班安排的员工不报告单一房间，仍照常检查未分配与早晚目标。
- 新版本保存规则快照；已有版本重排后才使用新目标。

**红黄普通班的顺序约束（V1.8）**

- 每个员工的红、黄房间普通班合并按工作段循环：早→中→晚→早。红房间早段之后，即使切到黄房间，下一次也必须中段。
- 同一工作段内部仍同房间同班，不按日期逐日切换。4天和6天工作段各推进一次，部分日期休假不重复推进。
- 白班、光子、自定义、加班、整段假期和未分配不推进、不重置普通班轮转。下一次红黄普通班接上一次顺序。
- 跨月未结束的段先续原房间原班；续段只算一次，新工作段才推进到下一类别。无历史时允许错峰起步，之后严格循环。
- 顺序优先于早晚段目标和房间偏好。轮到的类别无可用需求时，可安排非红黄班或保留未分配，不跳序或重复同类班凑人数。
- 人工锁定和补空位保留的已有班次不被删除。若违反顺序，报告H07硬冲突，允许保存草稿，确认前需调整或解锁重排。
- 新版本保存轮转规则快照，旧版本继续按原快照查看；重新生成后采用新顺序。


| 规则 | 强度 | 执行口径 |
| --- | --- | --- |
| 普通班配对 | 硬约束 | 每个启用班恰好2人，同房间同班，搭档可变 |
| 每日唯一与任职 | 硬约束 | 自动只排任职有效员工，同员工同日最多一个安排 |
| 计划与实际保护 | 生成约束 | 保留人工不可用、加班、自定义和锁定普通班 |
| 段内一致与跨月 | 硬约束 | 自动段内普通班一致，跨月先续原班；人工混班为P05提醒 |
| 光子轮换 | 固定约束 | 可续上月光子原段，该员工本月不新开光子段，优先白班 |
| 早中晚循环 | 生成硬约束 | 红黄普通工作段按早→中→晚→早，不连续同类段 |
| 月内房间分散 | 优先目标 | 覆盖与硬约束内每人至少两个房间，未达成提示P04 |
| 早晚目标 | 优先目标 | 在顺序约束内按名单顺序优先完整早、晚工作段 |
| 相反房间 | 优先目标 | 早、中、晚分别按上月同类别房间累计天数取相反房间 |
| 同类别平票 | 固定判断 | 红橙天数相同，取最后一次安排房间，再取相反房间 |
| 无类别历史 | 无偏好 | 没有该类别历史则不虚构房间偏好 |
| 容量不足 | 报告缺口 | 不覆盖保护安排，不用自定义补普通班人数 |

例：上月红早、橙中、红晚，则本月优先橙早、红中、橙晚。“黄房间”与系统橙房间是同一房间。

跨月续班、每日两人优先于相反房间偏好。无法同时满足时可用原房间补足并提示偏好未满足。早晚目标按员工名单顺序逐人比较；无法满足的人员继续补剩余需求，不能突破两人规则。

生成流程先读取上月有效版本及历史递延。分析工作段、已达成目标、缺项、光子和房间经历，形成任务快照。再固定目标月计划和人工保留格，建立目标月工作段，按日匹配候选。

尝试候选时，优先减少缺口和超额。先补历史早晚欠项，再按名单满足当月早晚目标。随后补其他递延并优化房间偏好。报告缺口不代表已经证明业务无解，超时不写入半成品。

提供“仅补空位”“重排未锁定格”。两者都保留自定义、加班和已锁定普通班。解锁后若落在计划休假或休息日，两种生成均恢复计划状态；补空位保留其他已排普通班，重排可重新分配未锁定班。

### F9. 任意月份编辑、自定义与清空

**人工混班（V1.10）**

- 允许人工将同段改成“中、早、早、早、早”，另一人改成“早、中、中、中、中”。
- 同房间或跨房间均可人工调整。需同时核对其他搭档，使每天每班仍恰好2人。
- 明确人工操作产生的混班段记录为例外，报告P05提醒，不因段内不同班而阻止确认。
- 单边调整导致1人或3人、任职错误、关闭班次排班、计划休假普通班仍是硬冲突。
- 原段可工作日期原为同房间同班时，修改前保存原班段依据，并记录原来已不可用的休假日期。仅一天手工改变班次或状态时，按已记录的原类别计达成，不额外计算新类别；例如“中、早、早、早、早”仍计原早段。多日混班且未恢复同班则不计完整段。没有原段依据时不按多数班次猜测。若影响相邻旧段的轮转参照，提示人工例外。
- 自动生成仍保持整段同房间同班。没有人工调整依据的自动混班仍报H04硬冲突。
- 自动重排按最近一次红黄普通班继续早→中→晚。填空保留已有班，重排只保护锁定格。
- 要完整保留人工混班，请锁定该段所有已有普通班。多个受保护班次矛盾时，不向该段新增自动班次。


月度表展示全部员工和当月全部自然日。无班表月份直接展示空白网格，首次保存建立草稿，不要求先自动生成。停用或任职期外员工允许人工编辑，但报告任职硬冲突，自动排班不新增其班次。

任意格可在八个普通班与休息、预定休假、请假、加班、未分配、自定义之间修改。全局停用班也允许人工选择，但需求不随人工修改而启用。休息、假期和加班不再阻止单格或批量编辑。

单格可改本日或整个工作段；加班单格操作仅本日。批量支持逐格、整行、整列、全选和Shift矩形，覆盖所有状态。筛选、月份或版本变化时清空选择。整批校验后保存，失败不部分写入。

普通人工班默认锁定；主动解锁后重排遵循工作日历和休假计划。月度编辑只改实际班表，永不反写开班日或独立休假计划。手工改变一个员工不自动调整搭档。无需输入任何调整原因，系统记录日期、状态和时间。

人工冲突允许保存，立即报告人数、段内一致、任职、光子和计划差异。存在硬冲突仍不可确认。已确认及历史导入版本的修改建立修订草稿，原版本保留。

**自定义班次**

- 月度表选择“自定义班次”，填写1至30字名称；支持复用已有名称、单格及批量设置。
- 不绑定房间，不受开班日、假期或普通班启用开关限制，不要求两人成组。
- 自动排班始终保留自定义格并跳过该员工当天，不提供自动分配或解锁后自动覆盖。
- 自定义不计八班覆盖、轮换或普通完整段；实际出勤按1人天统计，并按名称单列。
- Excel使用明确自定义标记，矩阵与结构化明细往返保留名称；未知普通标记仍报错。JSON备份保存名称。

**加班与清空**

加班是独立出勤状态，可从任意状态改入或改出。自动生成保留，不占八班名额。撤销时恢复有效计划或原状态；直接改为其他状态则采用人工选择。

清空当月移除全部普通班、自定义和加班，不受当前筛选限制。保留工作日历、独立休假计划和实际不可用状态；加班恢复原不可用状态；原状态为普通班或自定义时一并清除。每次建立子草稿，原版本完整保留，其他月份不变。

验收：未生成月份可编辑；周末或休假改班成功且计划不变；所有状态可批量互改。锁定重排保留，解锁恢复计划。自定义在两种自动模式中保留，缺人仍报告。硬冲突阻止确认，清空和修订均可找回原版。

### F10. 多维统计展示表格

统一筛选：月份或日期范围、版本、员工、房间、班次类别、是否包含未确认草稿。默认展示当前查看版本，并明确版本状态。所有表格支持排序、合计、点击数字下钻到明细，建议支持Excel导出。

| 统计维度 | 主要列 | 统计意义 |
| --- | --- | --- |
| 员工×月份 | 出勤天、早/中/晚/白/光子天数、房间数、各房间天数、预定休假、事后请假、休息、未分配 | 个人排班构成 |
| 员工×自定义班次 | 员工、名称、人天、日期明细 | 独立核对自定义安排 |
| 员工×工作段 | 段起止、归属月、房间班次、可工作天、实际排班天、是否完整、跨月标记 | 早晚目标与连续性核对 |
| 日期×班次 | 房间、应排2、实排、缺口、超额、配对人员、是否有效成组 | 每日覆盖情况 |
| 房间×月份 | 启用班次数、应排人天、实排人天、覆盖率、缺口人天、超额人天 | 房间人力投入 |
| 班次类别×月份 | 早/中/晚/白/光子人天、占比、房间分布 | 班次结构 |
| 员工×上月/本月 | 上月各类别房间天数、早中晚优先房间、光子段、本月达成 | 轮转核对 |
| 递延×月份 | 员工、来源段、待完成班次、产生月、计划月、完成段、状态 | 跨月任务追踪 |
| 异常×规则 | 缺人、单人班、锁定冲突、段不一致、光子禁排、未分配人数 | 问题定位 |

统计口径建议：

- 1条“员工+日期+班次”有效明细计1人天。同一员工同日不重复计。
- 实际排班天数不等于工时。加班和自定义计入总出勤并单列，不计入八班覆盖和轮转。定位、U不计入班次统计。
- 应排人天为选定范围内需求人数之和；关闭日/关闭班需求为0。
- 缺口人天为各日各班的max(应排−实排,0)之和；超额单列，不能抵消其他班缺口。
- 人数覆盖率为各班min(实排,应排)之和除以应排合计。应排为0时显示“—”。
- 成组达标率为恰好两人的启用班数除以启用班总数。单人班即使有1人也不算成组达标。
- 班次占比为该类别人天除以全部已排人天；分母为0时显示“—”。
- 早晚达成统计完整工作段，或有原段依据的单日人工调整例外；不能用空白段中“有一天早班”替代完整早段。跨月段同时显示当月贡献天数。
- 员工统计包含任职有效日期及已保存人工实际安排；任职期外安排仍提示硬冲突。
- 计划人天与实际状态分开；实际预定休假、事后请假、休息互斥计数。

最小核对例：某日八班应排16人，只排15人，某班仅1人。人数覆盖率为15/16，成组达标率为7/8，该版本仍有硬冲突，不能确认。

### F12. 版本、保存与导出

自动生成写入新草稿，历史已确认版本可追溯。修改上月数据、名单顺序、日历或规则后，受影响的下月草稿标记“输入已变化”，要求重新校验；不得继续显示为基于最新历史。

同一月份可有多个草稿，保留一个当前确认版本指针。确认后修改建议创建子草稿。统计默认随当前查看版本切换，不能混算多个版本。

建议首版提供月度表、统计表和明细的Excel导出，带年份月份、图例、版本状态。增加“员工休假计划”和“事后请假”独立明细页。预定休假/事后请假/休息保留各自底色和文字，避免导出后再次导入时丢失语义。

## G 已确认的业务口径与风险

本次三个决策已确认：人工普通班默认锁定保留，主动解锁后按计划重排；房间轮换按同类别累计天数，平票取最后一次；人工冲突可保存，但硬冲突阻止确认。

光子续段和假期不切段为固定规则，不再提供待定选项。中、白、光子不强制每人每月各一段。多余人员标未分配，不自动新增备用班或自动休假。

自定义和加班优先保留，可能导致普通班缺人。计划和实际可不同，但普通班在休息日或计划休假日仍会产生硬冲突；负责人可保留草稿或调整计划后再确认。

历史颜色、缺失续段、计划变化及人工编辑均可能影响后续月份。通过导入预览、来源版本快照、输入变化提醒和报告处理；已有历史不被静默重写。

本地数据不自动同步；需要定期导出完整备份。固定登录口令不替代设备访问保护，不引入审批或账号权限扩展。
