## A 产品概述

版本：V1.6。日期：2026-11-03。

本系统面向排班负责人。以员工名单、目标月日历及休假为输入，生成月度排班草稿。有上月记录时延续轮转；没有上月记录时按其余规则首次排班。负责人在月历中检查缺口、改班并确认版本，统计表与该版本同步。

本文包含产品需求、数据字典、排班流程、线框图与验收要求。配套纯前端系统已实现。本版增加休息和预定休假的月度编辑保护。加班支持登记、撤销、统计与Excel往返，首页支持月份切换。

需求依据是用户提供的五月、六月截图及后续文字说明。黄色格已明确为排班前预定休假，请假用于排班后调整。截图没有明确年份，仅用于理解结构与图例，不将截图中的每个历史安排当作新规则的标准答案。

已按 [phuryn/pm-skills](https://github.com/phuryn/pm-skills) 的 create-prd、user-stories、test-scenarios 方法完成拆分。开源技能提供分析框架，业务规则来自用户说明。

本文约定三类标记：**已确认**是用户明确提出；**方案建议**是本稿提出的产品处理方式；**待决定**是尚不能唯一确定的业务口径。待决定项不得作为已批准算法实现。

## B 背景与问题

现有表格以员工为行、日期为列，颜色表达房间，文字表达班次或特殊状态。人工排下月班时，需要同时核对上月轮转、跨月工作段、随机请假、每日两人配对与名单顺序。

直接复制上一月再修改容易覆盖休息或请假，也难以解释为何某人没有排到早班或晚班。人数不足时，系统必须说明缺口，不能通过单人班、重复安排同一员工来拼出完整表格。

用户新增了统计要求。因此同一份排班数据应同时支持月度查看、员工统计、房间统计、班次统计及跨月轮转核对。

已确认的房间与班次：

| 房间编号（建议） | 房间展示 | 允许班次 | 每个启用班次人数 |
| --- | --- | --- | --- |
| ROOM-B | 蓝底房间 | 白班 | 2人 |
| ROOM-R | 红底房间 | 早班、中班、晚班 | 每班2人 |
| ROOM-O | 橙底房间 | 早班、中班、晚班 | 每班2人 |
| ROOM-P | 无色底房间 | 光子班 | 2人 |

合计四个房间、八个班次。在八班都启用的日期，需要16名不同员工。系统中的房间名称可由负责人改成实际名称，颜色只是房间的展示属性。

## C 目标与成功标准

支持两条流程：已有历史时导入并生成下月；没有历史时先导入员工，再配置日历与休假直接排班。两者均支持手工修订、确认与统计。

以下是产品验收目标建议，不是已经测得的成效：

| 指标 | 验收目标 | 衡量方式 |
| --- | --- | --- |
| 受保护单元格 | 自动生成覆盖休息、预定休假、事后请假及人工锁定格的次数为0 | 比较生成前后值与锁定状态 |
| 排班有效性 | 可确认版本中，启用班次全部恰好2人，员工同日最多1班 | 对整月逐日校验 |
| 跨月可追溯 | 每个续排工作段和递延任务都有来源 | 从月历进入段详情和递延清单 |
| 未满足可解释 | 所有缺口、跨月硬冲突与软目标未满足都有原因 | 检查生成报告与统计 |
| 统计一致性 | 所有统计可回到明细核对，且绑定同一排班版本 | 对照员工、日期、房间明细汇总 |
| 响应时间 | 建议以50人、31天为首版基准，10秒内给出结果或明确求解中状态 | 由开发阶段建立基准并实测，不承诺任何输入均有解 |

保存有冲突的编辑草稿与确认有效排班是两种状态。草稿可保留用户修改，但不得把缺人或单人班标为有效排班。

## D 使用人群与使用场景

| 用户 | 主要任务 | 首版入口 |
| --- | --- | --- |
| 排班负责人（主要用户） | 维护员工和名单顺序、休假、导入、生成和改单元格 | 月度排班、基础资料、导入 |
| 排班核对者（建议角色） | 检查班次人数、跨月轮转和统计，确认排班版本 | 冲突报告、统计、版本详情 |

两种任务可由同一个人完成。首版不要求建设复杂的审批组织；谁能编辑、谁能确认可先设为简单权限。

关键场景：新增员工后排下月班；月末同班继续到月初；请假导致原搭档变动；调休后周六开班、工作日休息；生成后改某人某日的班；主管查看月度人员与房间负荷。

## E 用户价值

| 价值要素 | 排班负责人 | 排班核对者 |
| --- | --- | --- |
| 谁 | 每月制作排班表的人 | 检查排班与统计的人 |
| 为什么 | 需要同时满足多人、多班、多月规则 | 需要发现缺口并核对轮转情况 |
| 目前做法 | 对照上月Excel逐格填写 | 逐行逐列点人数，另做统计 |
| 系统如何帮助 | 自动保护休假、按规则生成、提示冲突 | 按版本汇总、按原因筛选、点击查看明细 |
| 预期变化 | 保留人工控制，减少重复填写和漏查 | 发现问题后能定位到人员、日期与规则 |
| 可用替代 | 继续使用Excel和人工核对 | 手工汇总Excel透视表 |

系统的核心价值是把轮转、跨月、保护格与两人配对放在同一次校验中，并能解释没有排满的原因。实际节省时间需在试用中测量。

## F 方案与功能需求

### F1. 信息结构与主流程

```flow LR
首次准备 -> 员工导入: 只有名单
首次准备 -> 历史导入: 有班表，可同时建员工
员工导入 -> 历史导入: 可选
员工导入 -> 月度准备: 无上月也可继续
历史导入 -> 月度准备: 使用历史轮转
月度准备 -> 自动生成: 工作日历与休假计划
自动生成 -> 月历修订: 草稿与报告
月历修订 -> 事后请假: 单独调整
事后请假 -> 月历修订: 重新核对
月历修订 -> 校验确认: 检查规则
校验确认 -> 统计与导出: 绑定版本
```

工作台提供上月、下月、直接选择月份和回到本月入口，复用全局所选月份。切换后在册员工、开班日、成组率、冲突、排班预览及房间人天同步更新。无班表月份显示空态；查看完整排班、日历、导入、生成等快捷入口沿用所选月份，生成面板明确目标月。

主导航包括月度排班、员工管理、房间与班次、工作日历、Excel导入、统计分析、规则与版本。首版只做一个排班单元，多部门隔离留待后续。

### F2. 员工管理

- 新增、编辑、停用员工；使用唯一员工编号，同名人员不得自动合并。
- 维护姓名、排班顺序、生效日期、离职/停用日期、备注。
- 可调整名单顺序。生成前展示顺序，生成结果保存顺序快照。
- 历史已被排班引用的员工以停用处理，保留历史排班与统计。
- 新员工没有上月记录时展示“无历史”，不编造上月房间或光子经历。
- 不存固定搭档。两人组合随实际可用情况形成。

员工是否限制房间或有固定岗位尚未确认。首版不默认存在特殊岗位豁免；后续可扩展可排班次范围。

**员工名单Excel导入**

支持只含员工资料的工作表，无需日期或班次。字段为员工编号、姓名、顺序、生效日期、停用日期、备注；可映射自有表头。

姓名必填。无编号时按唯一姓名匹配现有员工，无法匹配则自动编号。同名歧义和重复编号必须处理，不能自动合并。

顺序从1开始，留空时保留已有顺序，新员工按文件顺序追加。日期可留空；新员工表示不限，已有员工保留原值。停用日期起不再排班，必须晚于生效日期。

预览新增/更新人数、具体资料及逐行错误，可跳过错误行。相同编号更新需明确勾选确认；不删除未列入的员工，不生成班表。整批保存，失败不写入部分数据。

### F3. 房间、班次与需求管理

- 预置四房间、八班次，保存独立编码、名称、显示颜色及启用状态。
- 班次绑定房间，分别识别红早与橙早，同时保留“早班”这一统计类别。
- 需求按日期、房间和班次保存。启用时人数固定2，关闭时为0。
- 默认开班日八班全开，允许按日关闭班次；保存写入操作记录。
- 本期无需配置具体上下班时间。没有真实班次时长前不计算工时。
- 黄底预定休假、紫底事后请假和深灰/黑底休息是人员状态，不是房间，也不加入八班次。

**月度需求日历**

- 用整月周一至周日日历替代逐日切换；支持上月、下月和直接选择月份。
- 每天显示开班/休息、启用班次数、所需人数、各房间启用班次数及单日配置标记。
- 单日模式点击日期后在侧栏设置八班启闭，统一保存；休息日只读并提供工作日历入口。
- 多选模式支持不连续日期、日期范围、全选开班日和清除选择。范围选择替换当前选择，休息日自动跳过且不可选。
- 每个班次提供保持不变、启用2人、关闭0人、恢复默认。跨日期不一致时显示部分启用，默认保持不变，避免覆盖无关班次。
- 提供全部启用、全部关闭、恢复默认快捷操作；预览变更数量后整批保存，失败不写入部分数据。
- 恢复默认删除日期覆盖，跟随全局班次开关。全局停用班次不能单日启用，须先修改全局开关。
- 切换月份清空日期选择及未保存动作，切换单日或模式清空未保存动作；页面明确提供保存按钮。
- 配置仅用于后续生成，已有版本的需求快照和班表保持原样；输入变化提醒继续生效。

**验收：**单日修改只影响该日指定班次；批量选择不连续日期仅修改这些日期。选择含周末的范围只处理开班日，调休开班日可选。保持不变保留各日差异，恢复默认消除覆盖；刷新页面仍保留已保存配置。旧班表不变，新生成版本采用更新需求。

### F4. 月度工作日历、休假计划与事后请假

**已确认：**默认周末休息，支持节假日调休。休假是排班前预定，请假是排班后调整；两者分开配置。

工作日历提供四个页签：开班日历、员工休假计划、事后请假、个人休息。月份统一切换，默认进入员工休假计划。

| 配置 | 何时使用 | 展示及影响 |
| --- | --- | --- |
| 全局开班日历 | 排班前维护，后续可调整 | 周末默认关闭；可把指定日期改为开班或休息；影响全体八班需求 |
| 预定休假计划 | 排班前确定员工当月休假 | 黄色“预”；独立计划记录；仅让对应员工在选定日期不可排班 |
| 事后请假 | 原班表确定后临时调整 | 紫色“请”；替换当日班次；独立列表维护；原休假计划继续保留 |
| 个人休息 | 员工个人调休 | 深灰“休”；只影响此人；不改变全体开班需求 |

**F4.1 配置当月休假计划**

- 选择员工和月份，按单日、日期范围或不连续日期配置，填写说明。
- 范围选择可仅选开班日，或选全部自然日。保存前展示具体勾选日期与天数。
- 仅允许该月、任职有效期内日期；同员工同日不可重复建计划。
- 可在排班生成前直接维护，无需先有正式班表。保存后即作为自动排班输入。
- 修改已排月份时，提示将被替换的班次数；已确认版本建立修订草稿。
- 没有休假的月份可以直接生成，不要求创建空计划或额外审批。

**F4.2 休假计划表格**

主表以员工为行、当月28至31个日期为列，右侧汇总计划天数。显示姓名、唯一编号、开班/休息背景；黄色“预”标记休假。

点击空格可新增计划；点击黄色格可编辑所属计划。下方明细表展示员工、具体日期、天数、说明及编辑/取消操作。支持员工筛选和不连续日期调整。

取消部分日期可在编辑中取消勾选；整条计划通过明确的取消操作移除。取消后开班日恢复未分配，休息日恢复休息，不自动恢复原班次。变更后需要补排并重新核对配对。

**F4.3 事后请假单独配置**

事后请假支持员工、单日或日期范围、原因。独立列表按员工和日期展示，可编辑日期及原因、撤销单日请假。月度排班格也可登记事后请假。

事后请假不自动调整搭档，不减少班次需求；系统重新核对人数及工作段。两类假期在自动重排和补空位时均保留，不依赖手工锁定开关。

**F4.4 重叠、撤销与统计**

同员工同日同时有计划和请假时，实际排班显示请假，独立计划仍保留。计划表以“请”角标提示重叠。

撤销事后请假时，先恢复该日预定休假；若无计划，按全局日历恢复休息或未分配。修改或取消休假计划时，不删除事后请假。

休假或请假落在全局休息日时，该日仍保留休息边界，不因此连成跨周工作段。

计划表按计划日期统计人天；实际班表分别统计预定休假和事后请假人天。同日重叠只计入事后请假，不计出勤，也不计入未分配。计划人天与实际状态人天可能不同。

### F5. 历史数据与Excel导入

首版建议支持 `.xlsx`，兼容两个输入模板：员工×日期的历史表，以及结构化明细表。旧 `.xls` 提示转存为 `.xlsx`；CSV可后续支持，但不能保留底色。

导入按四步进行：选择文件与用途 → 映射表头、人员、日期、颜色、文字 → 预览并解决错误 → 确认写入。

导入用途分为员工名单、上月历史、排班前休假计划、排班后事后请假、个人休息、目标月人工排班。计划和请假分别选择用途，空白格不撤销已有记录。

| 项目 | 处理要求 |
| --- | --- |
| 人员识别 | 优先员工编号；仅姓名匹配时需消除同名歧义；新员工由用户确认创建 |
| 日期 | 表头只有日数时必须选择年份和月份，校验月份实际天数 |
| 房间识别 | 底色映射到房间；支持深灰映射休息，黄底映射预定休假，紫底映射事后请假 |
| 班次识别 | 早、中、晚、白、光子映射到班次类别，尾部U忽略，但保留原文 |
| 加班 | 独立状态，保留原休息或休假，计出勤并单列，不占八班需求 |
| 非排班文字 | 定位保留原始附注，不参与需求和轮转 |
| 未知标记 | 不默认当休假或空白；阻止受影响数据确认，要求修正映射 |
| 颜色文字冲突 | 如蓝底写早班，展示冲突并要求确认；不静默当成白班 |
| 合并单元格 | 表头按预览映射；人员日期区域的跨格歧义需人工解决 |
| 历史有效性 | 可导入有历史例外的数据并标警告，不能将历史警告自动变为新规则豁免 |
| 写入与回退 | 确认前不影响现有版本；同批次全成或全败；重复导入先展示差异 |

主题色、近似色及条件格式产生的显示色都需要可确认的映射。读取不到实际底色时要求人工映射，不猜测。图片没有Excel原始单元格数据，本稿未宣称已导入或验证真实工作簿。

**F5.1 首次初始化方案**

首次打开默认使用空白工作区：没有员工、班表或演示安排。保留四房间八班次和默认周末日历。演示数据仅由用户在设置中主动载入。

| 用户已有资料 | 初始化路径 | 后续操作 |
| --- | --- | --- |
| 只有员工名单 | 导入员工名单，核对编号、顺序和有效日期 | 配置当月日历与休假，直接首次排班 |
| 已有上月班表 | 可直接导入班表，确认创建未知员工 | 使用该历史生成目标月；无需重复录入名单 |
| 名单与班表都有 | 先导名单，再按编号匹配已有班表 | 保留员工主键，不重复创建 |
| 均无Excel | 在员工管理手工添加 | 配置休假后首次排班 |

工作台显示三个步骤：准备员工、导入上月（可跳过）、配置日历与休假后生成。支持选择目标月。导入上月时默认该目标月的前一月，历史导入完成回到初始化步骤。

没有在职员工时禁止生成并提供导入入口。八班全开需要每日16人；人数不足仍报告缺口，不因首次使用放宽两人成组。

提供两份空白模板：“员工名单模板”只含员工资料及说明；“初始化导入模板”含员工名单、已有排班及填写说明。模板不附带虚构员工行。已有排班可填写“红早/橙晚/白/光子”等明确文字，或使用映射底色。

### F6. 数据库与数据字典

数据库建议按以下业务实体拆分。编号、颜色和实体名称是实现建议；字段用于约束功能，开发时可按技术方案调整。

| 实体 | 核心字段 | 关系与约束 |
| --- | --- | --- |
| Employee 员工 | id、code、name、sort_order、active_from、active_to | 编号唯一；姓名不唯一；历史引用不可随停用删除 |
| Room 房间 | id、code、name、color、active | 房间颜色不作主键 |
| Shift 班次 | id、code、room_id、category、active | category为早/中/晚/白/光子；一班归一房间 |
| CalendarDay 全局日历 | date、is_open、override_reason | 日期唯一；周末默认关闭，允许覆盖 |
| Demand 每日需求 | date、shift_id、required_count | 日期+班次唯一；本期只允许0或2 |
| VacationPlan 预定休假计划 | id、employee_id、month、dates[]、reason、source、created、updated | 独立于实际班次；同员工同日唯一；支持不连续日期 |
| Availability 个人不可用 | employee_id、date、type、source、reason | 个人休息与事后请假；与预定休假分开配置 |
| ScheduleVersion 排班版本 | id、month、status、parent_id、history_mode、source_version_id、rule_version、input_snapshot | 草稿/有冲突草稿/已确认/历史导入；生成依赖可追溯 |
| Assignment 排班明细 | version_id、employee_id、date、shift_id、locked、source、segment_id | 同版本员工+日期唯一；休息/休假/请假/加班是明确状态；加班保存overtimeBase原状态 |
| PairAssignment 两人班组 | version_id、date、shift_id、member1、member2 | 两成员不同；一人同日不能属于两个组；成员对应两条Assignment |
| WorkSegment 工作段 | id、employee_id、start、end、boundary_status | 跨月使用同一段标识；边界未知时不可标完整 |
| RotationLedger 轮转递延 | employee_id、type、origin_segment、due_month、status、fulfilled_segment | 区分续段、待白班、其他递延；同来源任务不重复建立 |
| GenerationRun 生成批次 | id、base_version、target_version、order_snapshot、status、duration | 保存输入快照、规则版本与结果报告 |
| ConflictIssue 冲突 | run_id、rule_id、severity、employee/date/shift、reason、suggestion | 能从报告定位回月历；不以颜色代替错误类型 |
| ImportBatch 导入批次 | id、file_name、purpose、mapping、raw_data、errors | 保存原文与颜色信息，支持差异预览与批次追溯 |
| ChangeLog 修改记录 | actor、time、entity、before、after、reason | 人工改班、日历变更、确认版本均可追溯 |

纯前端实现使用本地数据结构第2版，保存在独立工作区。不迁移或兼容旧版数据、旧版JSON备份。Excel黄色格按本版休假定义解析。

排班版本保存当时的休假计划快照。查看或导出历史版本时，不使用后来修改的计划覆盖历史。

PairAssignment可在实现中由排班明细派生，但提交前必须校验每个启用班恰好形成一对。统计应从版本对应的排班明细汇总，不另存一份可被随意修改的统计总数。

### F7. 工作段、跨月与递延定义

**已确认：**工作周不是固定五天，而是两次黑底休息之间的工作段。连续多天黑底应作为一个休息区间处理，不能生成多个零天段。

**方案建议：**按员工的个人休息边界识别工作段。段内预定休假和事后请假只扣除可工作日，不新建轮转段；月末不切断段。同段的可工作日期应保持同一房间同一班。两类假期是否中断工作段沿用同一配置，默认不切段。

工作段需保存起止日和“边界是否已知”。有上月参考时，目标月生成读取上月末所属段，以及目标月末之后第一个休息区间；无法确认下一边界时标为暂定，不能宣称已保证跨月完整性。

示意：某段从M月29日至M+1月3日，M+1月4日开始休息。29日排红早，则1日至3日仍为红早；同伴可换，但每天仍需红早两人。若1日已预定休假，该格保持黄色“预”。

**方案建议：**完整工作段按开始月份归属，用于“早晚各一段”目标统计；实际工作天数按发生月份统计。跨月两个月都显示续段，但不能把同一段重复记为两个已完成段。此归属口径仍需业务确认。

光子与白班规则只确认单向关系：上月有完整光子段，下月不再新排光子，并安排白班。不能自行推导“上月白班则下月必须光子”。部分光子段、跨月光子段如何触发禁排尚待决定。

中班、光子、白班因请假无法完成时，可以带到下月；递延记录应关联原任务。完成后销账，重复生成不能重复累计。没有确认月度轮转配额之前，不自动给每个人每月新增三条欠班。

**F7.1 无上月记录的首次排班模式**

**已确认：**没有紧邻上月班表时，仍可自动排班并手工调整。更早月份的班表不冒充上月参考。

**实现口径：**本月首日作为初始工作段起点。跳过上月光子禁排及转白触发、上月红橙轮转、上月跨月班次继承。其余规则继续执行：每天每班两人、同日唯一、不可用保护和人工锁定。段内同班、名单顺序、早晚优先及有效递延也继续执行。

“无上月参考”是说明性提醒，不单独构成硬冲突；满足其余硬规则即可确认。生成结果标记首次模式，支持单日或整段手工调整，再次生成继续保护人工安排。

月末仍延伸到下一休息边界。首月生成后，下个月使用该班表作为历史，恢复正常跨月和轮转规则。

模式与参考版本保存在版本中。后来补导上月，不静默改写旧首次版本；提示输入变化，重新生成或显式重新校验时才使用新参考。已有上月但缺少某员工的续段数据时，仍提示对应缺失，不能借首次模式绕过。

### F8. 自动排班规则

| 规则 | 性质 | 生成及补班阶段的处理 |
| --- | --- | --- |
| H01 保护休息/预定休假/事后请假 | 已确认，硬约束 | 自动生成永不覆盖 |
| H02 两人成组 | 已确认，硬约束，即用户所指第5条 | 每个启用班恰好2名不同员工，同房间同班；补班也不能放宽 |
| H03 同日唯一 | 必要一致性约束建议 | 同一员工同日最多1班，且在任职有效期内 |
| H04 跨月完整 | 已确认，硬要求 | 有上月时续原段；无上月时从本月首日开始；之后月份恢复正常续段 |
| H05 光子禁排 | 已确认，硬要求 | 上月满足光子触发条件者，下月不能再排光子，白班目标进入轮转 |
| H06 人工锁定 | 方案建议，生成硬约束 | 人工班次默认锁定；只能显式解锁或再次人工修改 |
| P01 早晚各一段 | 已确认，优先目标 | 按名单先满足早晚工作段；不足时列出未满足原因 |
| P02 红转橙 | 已确认，优先目标 | 上月红房间者优先橙房间；不覆盖未结束的原房间续段 |
| P03 递延任务 | 已确认允许递延，具体顺序建议 | 同优先级下先处理更早产生的待完成任务 |
| P04 稳定性 | 方案建议 | 同等满足程度下，减少已生成草稿的无关改动 |

硬约束互相冲突时，不静默选择其中一条放弃。可生成“有冲突草稿”和缺口报告，不能确认有效版本。

按名单顺序的实现要求：先固定全部硬约束，再依次优化员工个人目标。较前员工的偏好也不能使全体硬约束失效。若本次可行解中，第k位开始无法满足个人优先目标，记录此人为补班起点；k位及以下人员补余班，允许放宽早晚目标和房间偏好，所有硬约束继续校验。

补班起点是相对本次规则、快照和求解结果的解释，不可将超时直接显示为“业务无解”。有需要时在同级候选间回退搜索；同一输入和规则版本应能复现结果。

生成流程：

1. 校验员工、目标月日历与休假；有上月用历史模式，无上月用首次模式。
2. 建立启用班次需求与每日可用人员，先查16人容量和锁定冲突。
3. 有参考时识别跨月与轮转；无参考跳过上月相关要求，仍处理有效递延。
4. 固定休息、预定休假、事后请假、锁定格和可确定的跨月续排。
5. 在全体硬约束可行范围内，按名单顺序优化早晚、房间和递延目标。
6. 记录补班起点，使用后续人员补余班并形成每日两人组合。
7. 校验结果，生成草稿、缺口清单、目标达成情况与跨月说明。
8. 用户查看差异后保存目标版本。已有已确认版本不得被生成操作直接覆盖。

不足16人只是预检的一类问题；达到16人也可能因光子禁排、锁定、续段冲突而不可行。不能仅凭人数判定有解。

若可用人数超过16，建议将多余人员标为“未分配”。提示负责人处理，不自动加出第九类班，也不把他们标为请假或休息。待确认多余人员的业务去向。

### F9. 月历与手工编辑

默认展示员工×日期的整月表格，保留现有表格的阅读方式。冻结员工列、日期行，支持横向滚动、按房间/班次/员工筛选，并展示每日各班人数。另提供自然月视图，按日期汇总八班配对。

每格显示房间简称、班次文字、锁定图标和续段标记；休息格显示“休”，预定休假格显示黄色“预”，事后请假格显示紫色“请”。不得只用颜色区分状态。格子为空、不可用、未分配是不同状态。

点击单元格打开编辑面板：设置班次、休息、事后请假；休息和预定休假不得改成普通班次或恢复可用，必须先在工作日历调整；可选择加班。普通改班可选择仅本日或整个工作段，加班单格操作仅本日。手工操作允许保留有冲突草稿，但即时提示破坏配对、段内一致性或每日人数的后果。取消休假/请假/休息需明确操作，不通过自动生成取消。

人工批量改班默认锁定，可取消勾选。修改一个员工不静默修改搭档，可展示“同时调整另一名员工”的候选操作并由负责人选择。局部修复建议按受影响日期的全部八班、关联工作段及跨月依赖计算，不能只填一个格就声称整表有效。

生成前提供“仅补空位”“重排未锁定格”两种方式。生成结果展示新增、变化、未变化、缺口；重复生成保留保护格与人工锁定格。

**F9.1 多选调整与锁定（新增）**

- 在员工总览进入多选模式，点击切换可编辑格选择；Shift点击连选矩形，支持多员工、不连续日期、整行、整列及全选当前筛选员工。
- 选择范围只含当前月份、当前版本、任职有效期内的可编辑格。休息、预定休假、事后请假及已登记加班禁止选中，逐格、整行、整列、全选与Shift连选统一排除。切换月份、版本或可见员工后清空选择，避免误改隐藏人员。
- 工具栏显示已选可编辑格及可锁定、解锁的普通班次数量。全选和行列复选状态只计算可选格；没有可选格时禁用对应入口。单元格变为保护状态时自动移出已选范围。
- 批量调整可统一设置启用班次、未分配、个人休息或事后请假，填写同一原因。仅作用于所选当月格子，不自动扩展工作段或修改搭档。
- 已有休息、预定休假、事后请假和加班禁止选中，批量保存时再次跳过保护格。休息及预定休假的加班只能在退出多选后逐格登记。休息与预定休假的取消仅通过工作日历。
- 批量锁定和解锁仅更改已有普通班次的锁定状态，保留房间、班次和原因。未分配与保护格不会因此锁定或解锁。
- 解锁后允许“重排未锁定格”重新安排；“仅补空位”继续保留已有班次。
- 整批验证后保存。范围非法或写入失败不部分更新；成功提示处理及跳过数量。已确认或历史导入版本先建立修订草稿。
- 保存后立即重新计算人数、配对、工作段及确认资格，硬冲突仍阻止确认。

**F9.2 一键清空当月排班（新增）**

- 月度排班右上角提供入口，确认面板显示月份、当前版本、拟清除班次数和保留内容；没有班次时禁用。
- 清空当前查看版本的当月全部班次，包括自动、人工、导入、已锁定班次及加班。不受员工或房间筛选限制，不影响其他月份。
- 保留员工、工作日历、需求快照、个人休息、预定休假、事后请假及独立休假计划。被清除的普通班次恢复可用状态，关闭日期仍显示休息。加班恢复原休息或休假状态。
- 每次清空建立新的子草稿，即使源版本是草稿也完整保留原版本。原版可通过版本下拉框找回。
- 清空后即时更新人数和冲突报告，可重新自动排班或手工安排；未排满时不能确认有效版本。
- 记录清空月份和来源版本。确认前版本变化时拒绝执行，避免误清新版本。

新增验收：清空后当月班次为0，其他月份和两类假期不变，原版可找回。所有选择路径跳过假期和休息，不计入已选数量。锁定格经重排保持，解锁不改变班次。非法范围整批失败，刷新后保存结果仍在。

**F9.3 月度编辑保护与加班（新增）**

- 休息和预定休假格禁用普通班次、事后请假及恢复可用选项，仅可登记加班。普通班次恢复必须先在工作日历修改日历、个人休息或独立休假计划，不能通过未分配状态绕过。
- 加班是独立状态，显示蓝色“加班”，不扩充八班次，不占每日两人配对名额，不触发房间和光子轮转。
- 保存加班原因及原状态快照。原个人休息、预定休假计划及原因保留，计划表显示“加”角标。事后请假不能直接转为加班。
- 加班始终受自动排班保护，不提供解锁。单格登记仅本日；批量加班只处理当月可编辑工作日，休息和预定休假不参与批量选择。
- 撤销加班后优先恢复有效预定休假，否则恢复原个人休息或最新日历中的可用状态。修改或取消原计划不删除加班，只更新其原状态。
- 休息日上的加班保留休息边界。预定休假上的加班沿用原休假的段边界设置，不伪造完整普通班次段。
- 加班计入总出勤并单列人天，原休假与加班的实际状态不重复计数。覆盖、成组率及房间统计只计算普通班次。
- Excel月表和明细识别“加班”，导出保留原状态、原因及保护属性。重新导入后可撤销恢复。JSON备份校验原状态合法性。
- 清空当月排班同时移除加班并恢复原状态，来源版本仍保留。

新增验收：休息、预定休假不能直接或通过未分配变为普通班次。工作日历调整后可正常排班。单格与批量加班均可保存。撤销恢复原状态和原因，自动重排保留。周末加班不连周，Excel及JSON往返不丢状态。

### F10. 多维统计展示表格

统一筛选：月份或日期范围、版本、员工、房间、班次类别、是否包含未确认草稿。默认展示当前查看版本，并明确版本状态。所有表格支持排序、合计、点击数字下钻到明细，建议支持Excel导出。

| 统计维度 | 主要列 | 统计意义 |
| --- | --- | --- |
| 员工×月份 | 出勤天、早/中/晚/白/光子天数、红/橙/蓝/光子房间天数、预定休假、事后请假、休息、未分配 | 个人排班构成 |
| 员工×工作段 | 段起止、归属月、房间班次、可工作天、实际排班天、是否完整、跨月标记 | 早晚目标与连续性核对 |
| 日期×班次 | 房间、应排2、实排、缺口、超额、配对人员、是否有效成组 | 每日覆盖情况 |
| 房间×月份 | 启用班次数、应排人天、实排人天、覆盖率、缺口人天、超额人天 | 房间人力投入 |
| 班次类别×月份 | 早/中/晚/白/光子人天、占比、房间分布 | 班次结构 |
| 员工×上月/本月 | 上月房间/光子段、本月安排、早晚达成、红转橙情况、例外原因 | 轮转核对 |
| 递延×月份 | 员工、来源段、待完成班次、产生月、计划月、完成段、状态 | 跨月任务追踪 |
| 异常×规则 | 缺人、单人班、锁定冲突、段不一致、光子禁排、未分配人数 | 问题定位 |

统计口径建议：

- 1条“员工+日期+班次”有效明细计1人天。同一员工同日不重复计。
- 实际排班天数不等于工时。加班计入总出勤并单列，不计入八班覆盖和轮转。定位、U不计入班次统计。
- 应排人天为选定范围内需求人数之和；关闭日/关闭班需求为0。
- 缺口人天为各日各班的max(应排−实排,0)之和；超额单列，不能抵消其他班缺口。
- 人数覆盖率为各班min(实排,应排)之和除以应排合计。应排为0时显示“—”。
- 成组达标率为恰好两人的启用班数除以启用班总数。单人班即使有1人也不算成组达标。
- 班次占比为该类别人天除以全部已排人天；分母为0时显示“—”。
- 早晚达成统计完整工作段，不能用“有一天早班”替代“完整一段早班”。跨月段同时显示当月贡献天数。
- 员工统计的分母限定任职有效日期；停用前的历史记录仍参与历史统计。
- 计划人天与实际状态分开；实际预定休假、事后请假、休息互斥计数。

最小核对例：某日八班应排16人，只排15人，某班仅1人。人数覆盖率为15/16，成组达标率为7/8，该版本仍有硬冲突，不能确认。

### F12. 版本、保存与导出

自动生成写入新草稿，历史已确认版本可追溯。修改上月数据、名单顺序、日历或规则后，受影响的下月草稿标记“输入已变化”，要求重新校验；不得继续显示为基于最新历史。

同一月份可有多个草稿，保留一个当前确认版本指针。确认后修改建议创建子草稿。统计默认随当前查看版本切换，不能混算多个版本。

建议首版提供月度表、统计表和明细的Excel导出，带年份月份、图例、版本状态。增加“员工休假计划”和“事后请假”独立明细页。预定休假/事后请假/休息保留各自底色和文字，避免导出后再次导入时丢失语义。

## G 假设、待决定与风险

以下均已在方案中标记，评审时逐项决定；无需阻止其余模块的设计。

| 编号 | 待决定事项 | 本稿建议/当前安全处理 |
| --- | --- | --- |
| D01 | 上月末光子跨到下月，续段与次月禁排谁优先？ | 尚无业务授权的优先级；保留冲突草稿并阻止确认。可选“续完原段但不新开光子”，需另行确认 |
| D02 | 休假/请假是否中断工作段？不足几天是否还算完成一段？ | 默认两类假期均不切段；仅全部可工作日一致且至少有1天执行才记完成，完成阈值待定 |
| D03 | 早晚段按何月记完成？部分光子是否触发下月禁排？ | 建议段起始月计完整段，按发生月计天数；部分光子不自行触发完整段规则 |
| D04 | 同月红橙混排时如何判断下月房间偏好？橙是否也转红？ | 建议用上月早中晚有效人天较多的房间判断，持平不加偏好；橙转红尚未确认 |
| D05 | 中、光子、白的完整轮转顺序和每人月度配额是什么？ | 不强制每月五种班各一段；仅依据已确认目标和已有递延安排，避免制造无限欠班 |
| D06 | 多于16人的可用人员如何安排？固定岗位是否有例外？ | 建议标未分配并报告；未经确认不新增备用班、不自动休息、不默认岗位豁免 |
| D07 | 周末默认全部不开班，还是仅人员默认休息？ | 本稿建议全局默认关闭八班，可手动设开班并同步调整个人休息；需核对实际运营 |
| D08 | 单日人工改班能否突破工作段一致性？ | 允许保存冲突草稿；硬冲突清零后再确认有效版本 |
| D09 | 谁编辑、谁确认，是否需要审批？ | 建议简单编辑/确认权限，不引入多级流程 |

主要风险：历史颜色与新图例不完全一致、上月缺失段边界、休假造成整体无解、人工变更影响后续月份。对应措施是导入预览、明确首次模式、缺口解释、版本失效提醒。

性能风险：名单顺序、工作段、两人配对共同约束时可能需要搜索。超过时限应显示“尚未找到可行解”，区分已证明不可行与求解超时；允许保存候选草稿但不得自动确认。

## H 发布范围与验收方式

建议按可独立核对的交付里程碑推进，具体工期在业务口径确定和技术评估后估算：

| 里程碑 | 内容 | 完成条件 |
| --- | --- | --- |
| M1 基础数据 | 空白初始化、员工与班表导入、四房间八班次、日历、休假及请假 | 可把历史与下月不可用信息准确录入并回看 |
| M2 排班流程 | 工作段、跨月、名单顺序、动态两人配对、生成报告、月历编辑 | 满足硬约束的输入可生成有效表；无解能解释且不伪装成功 |
| M3 核对与交付 | 多维统计、版本确认、导出 | 统计明细可对账；修改与生成过程可追溯 |

首版不自动安排加班，不包含定位排班或统计工时，也不引入工资、考勤打卡、半天假、手机端员工换班审批。原始附注仍可保留，为后续扩展提供来源。

验收先用人工构造的小样本验证规则边界，再导入真实Excel核对颜色、日期、人员和已知跨月例子。历史样例存在例外时记录差异原因，不要求新系统逐格复刻旧表。

正式开发前需决定D01至D08中影响排班的业务口径。当前文档可用于产品评审、页面设计与基础数据模块拆分；含待决定规则的算法验收需随决策更新。
